# dsh-research-workbench 0.18.0

当前扫码流程：点击“扫码登录并选择应用”，在飞书页面先登录目标账号，再选择已有应用或创建新应用。工作台自动保存应用配置，并继续同账号的个人文档授权。已绑定用户点击“重新绑定 / 更换应用”执行相同流程。详见 [PRD 2036 实现与验收](prd-2026-11-02-qr-application.md)。下文旧版本交互记录仅供历史参考。

无需填写 App ID 或 Secret。选择已有应用需具备相应管理权限，企业审批仍由飞书控制。应用注册与个人文档授权分步进行，报告仍以个人身份保存。可取消待扫码流程；若远端已创建应用但本机保存失败，重试时选择该已有应用。高级用户仍可通过“手动配置已有应用”接入。

同一个 tgz 包用于 DeepSeek Harness 桌面版及网页版。安装后在侧栏点击“调研工作台”，独立主面板呈现调研任务、历史报告和 Codex 原生终端。

## 桌面版安装（Windows / macOS）

推荐使用 PRD 指定的“添加插件”弹窗：

1. 下载 `dsh-research-workbench-0.18.0-desktop.zip`，解压到准备长期保留的位置。
2. 打开 DeepSeek Harness，进入“插件”，点击“添加插件”。
3. 在“输入插件的包名、GitHub 仓库地址或本地目录路径”中，填写解压后 **dsh-research-workbench-0.18.0 文件夹的绝对路径**。该文件夹下直接有 package.json、plugin、server、dist、node_modules。
4. 点击“安装”，完成后按界面提示启用或重启，在侧栏点击“调研工作台”。

Windows 示例安装目录：`C:\dsh-plugins\dsh-research-workbench-0.18.0`；macOS 使用解压目录的完整路径。建议选择较短且准备长期保留的位置。两端使用同一个 ZIP，不需要 WSL 或外部 unzip 命令。

本机打包会生成 `artifacts/desktop-install-path.txt`，其中的整行路径可直接粘贴。不要填写 ZIP 文件、开发仓库目录或仅填写包名：目前未发布 npm，包名不能从 npm 搜索安装。

安装器可能保存本地目录引用，请保留解压后的目录，不要在安装后移动或删除。安装源默认“npm 官方源”可保留；本地目录包已内置运行依赖。

macOS 也可先完全退出桌面应用，再用它自带的 CLI 安装 tgz：

```bash
"/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh" plugin --profile desktop add "/绝对路径/dsh-research-workbench-0.18.0.tgz"
```

桌面应用运行期间使用内置插件页面安装；不要用全局 npm dsh 修改 desktop profile。

## 网页版安装

```bash
dsh plugin --profile web add "/绝对路径/dsh-research-workbench-0.18.0.tgz"
dsh web
```

安装前退出对应的网页服务；启动后使用 dsh 打印的认证链接进入，点击侧栏“调研工作台”。

## 历史调研

点击历史卡片默认显示报告；点击“AI对话”进入原终端会话。报告页不连接终端或重新调研；对话页可刷新、回放并继续输入。新建调研后仍实时展示终端。报告/对话切换支持浏览器前进后退。

## 默认行为

- 后端自动选择空闲的本机端口，安装后无需单独启动服务器或修改 YAML。
- 数据保存在 `$DSH_HOME/research-workbench`，未设置 DSH_HOME 时是 `~/.dsh/research-workbench`。不会自动复制开发项目 data 中的旧记录。
- Windows 建议 Windows 11 或 Windows 10 1903+，使用原生 Codex CLI；支持 x64/arm64。macOS 支持 Intel/Apple Silicon。
- Windows 自动从 PATH 或 npm 默认安装目录定位 codex.exe，避免直接启动 codex.cmd。自定义安装可配置 command 为原生 exe 的绝对路径，不要把参数拼进 command。
- Codex CLI 需在运行 dsh 的环境中可用并已登录；默认使用 Codex 自身的模型配置，可通过插件 config.model 覆盖。Node 运行时需支持 node:sqlite（>=22.13）。
- 本机使用；远程网页客户端不能连接运行在服务器上的 127.0.0.1 工作台。
- 包内包含后端依赖及 node-pty 预编译文件，无需安装时编译。保留了第三方依赖自带的许可证。包内检查四种 Windows/macOS 架构预编译文件；Windows 首次加载会准备对应 ConPTY DLL，macOS 会修复 spawn-helper 可执行位。实际平台验收状态见发布说明。
- 同一数据目录仅允许一个服务使用；若桌面和网页需同时打开同一份数据，请显式配置相同 dataDir 及固定 port，插件会验证并复用已启动的同库服务。

报告生成后由用户点击“上传飞书”，原终端 Agent 执行保存。未授权时由 Agent 提供授权二维码；平台不代写飞书。Codex 默认完整访问文件系统和网络，轮次结束后保留终端等待新要求。

## 使用当前项目的旧记录（可选）

在对应 profile 的 cordis.patch.yml 中追加以下配置，替换 dataDir 为旧 data 目录的绝对路径；保留原有内容：

```yaml
- id: dsh-research-workbench
  config:
    dataDir: /绝对路径/调研工作台/data
    port: 3088
    mode: codex
```

若原服务仍运行，仅同版本身份校验及数据目录匹配时才会复用。不同数据库占用该端口会提示错误。

官方依据：https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/desktop/README.md

## 飞书授权二维码

Agent 生成二维码后，平台接受 UTC 或带时区偏移的 ISO 到期时间。图片晚于回执生成时会自动重试加载，仍失败可点“刷新二维码”；到期后点击“重新获取授权二维码”，由原终端 Agent 重新发起授权，不重新调研。扫码完成后在原终端回复“已授权”。

## 工作台内嵌宿主原生会话（PRD 2036）

新调研复用当前 DSH 宿主的 Session、默认模型、工具、消息、输入框与历史记录，无需另外安装 TUI 或在工作台配置 API Key。点击“启动调研”后在调研工作台内显示原生消息与输入框，不跳转宿主主会话页；顶部保留任务标题、状态、返回和飞书报告链接。工作台没有报告详情页和报告/对话切换；点击“AI会话”继续同一会话。

新建调研前点击首页“绑定飞书”，通过 lark-cli 验证用户授权；未授权时扫码并点击“我已授权”。任务直接在同一原生会话研究并保存到飞书，只回传文档链接。工作台不保存新报告正文、不提供报告详情页；已发布卡片打开飞书文档，“AI会话”继续原会话。设置飞书根目录可提供文件夹链接，或首次创建默认目录并记住 ID，后续复用。历史数据保留，失败任务可在首页重试。

插件版删除“配置AI”入口。原生会话的模型和权限由 DSH 管理，新建调研 Session 默认标准模式（standard）与完整访问，即使宿主默认其他模式也不受影响；不修改宿主全局设置，历史会话不被强制切换模式。

本地开发验收并更新已安装插件：

```bash
npm run accept:update -- --profile desktop --host-smoke
```

该命令先运行完整自动验收，再验证真实隔离宿主和浏览器，成功后打包并安装到指定 profile；失败时停止，不安装。网页 profile 可指定 `--profile research-workbench`。Windows 桌面请使用添加插件弹窗安装生成的 ZIP 解压目录；本轮真实宿主验证在 macOS 完成。

## 0.18.0 文件夹链接与目录 ID

“设置飞书根目录”可以粘贴 `https://企业.feishu.cn/drive/folder/…` 文件夹链接，系统保存目录 ID，Agent 直接上传；不要求或申请目录列表读取、文档搜索权限。不填链接时首次新建默认“调研工作台”目录并记住 ID，后续复用。因为不读取目录列表，已有同名文件夹需要提供链接；创建结果不确定时提示核对，不重复建目录。

之前因目录读取权限失败的任务，更新后可在首页重试，复用原会话资料。已完成报告不迁移。

## 根目录配置方式

“按名字创建”与“使用文件夹链接”二选一。链接方式无需填写名字，不重命名已有文件夹；切换方式只提交当前输入。新调研 Prompt 与保存位置提示同步更新，历史报告不会迁移。

## 重新绑定飞书

首页点击“已绑定飞书”，再点“重新绑定”，扫描新二维码并点击“我已授权”完成账号核验。重新获取二维码会生成新流程，旧二维码失效；取消或生成失败不会主动注销当前账号。已有报告不迁移，可在根目录设置中指定新账号可访问的文件夹。

## 配置自己的飞书应用

“绑定飞书 / 已绑定飞书”→“配置自己的飞书应用”，填写 App ID、App Secret 后保存并扫码授权。使用独立 Lark CLI profile，不覆盖本机默认应用；Secret 不回显，同一 App ID 可留空保留已存凭据。可以切回本机默认应用。应用必须允许目标账号使用，目标文件夹也需对该账号可访问。失败任务重试可使用当前新应用恢复交付，原会话和历史执行配置保留。

## 0.18.0 扫码绑定账号与应用

点击“绑定飞书”会展示所选应用并自动生成账号授权二维码；扫描后点击“我已授权”完成核验。已绑定用户可点“重新绑定”更换账号；切换企业时先点“更换应用”，保存已有应用配置后自动生成新二维码。报告仍以个人身份上传，不自动创建应用，不申请目录列表或搜索权限。应用需要对扫码账号可用，目标文件夹需要该账号具备编辑权限。

## 0.18.0 换账号提示无应用使用权限

“重新绑定”先选择“继续使用当前应用扫码”或“换企业或应用”。二维码只更换账号授权，应用保持为上方展示的应用；不会自动切到新账号名下的应用。同企业账号请管理员加入应用可用范围；不同企业请先选该账号可用的应用。二维码旁提供“当前应用无法使用，换一个应用”入口；取消配置保留原账号。
