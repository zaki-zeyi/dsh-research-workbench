# PRD 1990：扫码绑定账号并授权应用

来源：[调研工作台 PRD](https://zcnnosk3k1j9.feishu.cn/wiki/Twspww4ZKiUQI8krBGlc2VCsnmr)，revision 1990。版本 0.16.0。

## 交互

点击“绑定飞书”，未绑定且已有应用时自动生成二维码，同时显示应用名称及 App ID。扫描后点击“我已授权”，后端核验账号、所需权限及应用 ID 后完成绑定。已绑定时保留状态，点击“重新绑定”才生成新二维码。关闭窗口不注销原账号。

点击“更换应用”选择已有应用；自定义应用填写 App ID 与 App Secret，或恢复本机默认应用。保存后自动生成新二维码，旧二维码失效。未配置应用时显示选择入口；网络或 CLI 失败时保留应用上下文并提供重试，不循环发起授权。

报告仍以个人身份上传。应用属于授权客户端，个人账号是数据访问身份；此流程不自动创建飞书应用，也不能绕过企业管理员的应用可用范围。换企业先选择该账号可使用的应用，再扫码；目标文件夹需具备编辑权限。不开通目录列表和文档搜索权限也能执行既有交付流程。

## 后端与数据

二维码响应包含 appId/appName，不包含 device_code、Secret 或 token。授权开始时固定应用配置快照，生成二维码、完成 Device Flow 和核验均使用同一 CLI profile。完成后应用 ID 不一致则拒绝完成绑定。应用配置仍存储在独立 CLI profile，Secret 通过 stdin 交给 CLI，不回显、不进入任务数据。不修改本机默认 CLI 应用，不改已有报告链接或会话。

## 验收

- 103 项 Node 用例：新增授权应用显示、固定 profile、默认应用途中变化拒绝完成绑定。
- 24 项 Chromium 用例：自动二维码、换应用后自动新二维码、账号重绑、无应用入口、失败重试、历史会话与凭据不回显。
- 隔离真实 DSH 宿主：原生会话、独立应用、个人身份命令与云端报告回执。
- 发布包：离线依赖、ZIP、Node/Electron 加载检查。

自动验收使用模拟飞书凭据，不创建真实应用或切换真实用户。
