# 调研工作台验收用例

对应 PRD：FR-01 全量调研专题。基线为本地单用户 MVP，2026-10-23。

## 执行

```bash
npm ci
npx playwright install chromium
npm run acceptance
```

测试夹具使用临时数据库。自动验收不依赖真实模型或飞书。后端使用 Node 内置测试器；页面使用 Playwright Chromium；`npm run test:live` 独立进行真实外部服务联调。

## 人工验收操作

1. `npm run build && npm start`，打开工作台。
2. 点击“新建调研”，检查方向必填，默认“全网”，Prompt 自动包含方向与来源。
3. 启动后马上刷新或关闭页面，再打开同一任务。预期后台继续，报告最终可读，右侧显示历史 AI 会话。
4. 点击返回，检查卡片标题、时间、状态与摘要；打开卡片，报告与记录相同，无额外执行。
5. 演示模式打开文档，预期明确显示“本地演示文档”，不能把它当作飞书成功。
6. 故障交互通过 Playwright 测试服务器验证，生产环境没有故障注入接口。

## 真实外部服务验收（待配置后执行）

1. 配置专用 Harness SDK profile、真实搜索工具和模型凭据；配置飞书用户 token 与目标文件夹权限。
2. 将服务设为 live，运行 `RUN_LIVE_ACCEPTANCE=1 npm run test:live`。
3. 脚本预期：同一创建请求不重复产生任务，报告含来源，发布成功，飞书链接存在，历史读取不增加执行。
4. 人工核对：目标目录正确，链接可打开，正文完整，引用可访问，摘录来自实际资料，普通授权用户可读。
5. 模型网络故障后重试，旧草稿和会话保留；飞书授权过期或写入失败时报告保留，恢复授权后仅重试发布。
6. 飞书创建结果不确定时先核对目录；不得为“通过验收”直接清除创建检查点或反复新建。

协议模拟不能替代真实模型检索、账号权限和飞书 API 联调；本次交付需在验收报告中分别列明。
