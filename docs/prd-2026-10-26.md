# PRD 业务规则更新 · 2026-10-26

来源：[调研工作台 PRD](https://zcnnosk3k1j9.feishu.cn/wiki/Twspww4ZKiUQI8krBGlc2VCsnmr)，本次读取页面显示“今天修改”。

新版业务规则的关键原文：

> ai任务的默认prompt是：“帮我在【数据源】进行【调研方向】的调研，整理成带数据来源的报告，得到的结果保存到飞书文档，并呈现飞书链接（如果没有授权提供授权二维码给我）”。数据源默认全网。
>
> 飞书保存工作交终端的agent完成，平台本身不做飞书保存。
>

| 更新 | 实现 |
|---|---|
| Prompt 包含未授权时提供二维码 | 前端预览和服务端默认 Prompt 同步更新 |
| 展示 Agent 结果 | 读取当前终端的交付回执，展示飞书链接、待授权二维码、保存失败或进行中状态 |
| 收尾不提前中断保存 | 有效报告先归档展示；只有 Agent 回传保存成功、待授权或失败后才结束本轮，保持 PTY 连接 |
| 授权后继续 | 同一终端继续保存已有报告，回执更新即可刷新界面，不增加调研次数 |
| 异常保留 | 报告、来源、历史会话和本地副本保留；研究失败可重试，保存/授权在原终端继续 |

平台旧的 `POST /api/tasks/:id/publish` 返回 410，不能再触发平台上传。平台没有新增 OAuth 页面；上一方案的服务端 token 发布路径已从生产启动链路移除。旧飞书发布器仅保留在隔离兼容测试中。

## Agent 交付协议

每个任务有独立的 `report-<terminal>.json`、`delivery-<terminal>.json`、`feishu-auth-<terminal>.png`。报告 JSON 的结构仍为 title / summary / markdown / sources。

交付回执只包含必要的公开结果：

```json
{"status":"publishing"}
{"status":"published","url":"https://example.feishu.cn/docx/ActualDocumentToken"}
{"status":"awaiting_authorization","authorizationUrl":"https://accounts.feishu.cn/实际授权地址","expiresAt":"2026-10-26T12:00:00.000Z"}
{"status":"failed","error":"不含凭据的失败原因和下一步"}
```

`expiresAt` 可省略。Agent 使用官方 CLI 返回的实际授权 URL 生成 PNG；device code、access token 等不得写入回执或终端输出。授权二维码只在待授权时从任务工作目录的固定文件展示；无 PNG 时展示终端指引，成功保存后不再展示二维码。

二维码、链接和成功状态均由 Agent 回传，平台只校验结构与链接域名，不能独立证明飞书远端文档的正文正确性。真实扫码及远端正文仍需用户完成授权后联调确认。
